Diamond-blocked Metal engine: dispersive materials on the GPU (snapshots cg22, cg23), 2026-11-04
================================================================================================
cg22 = 57511e8 (v0.37.0-28-g57511e8) on speed-m5-gpu: Engine_Ext_LorentzMaterial (Drude/Lorentz materials and the
conducting sheets, an order-2 Lorentz extension with voltage ADEs) on the GPU. cg23 = 452f905 (v0.37.0-29-g452f905):
+ Engine_Ext_DebyeMaterial. Both only as exactly those classes (typeid), not as subclasses. The CPU code changes only by
friend declarations (engine_ext_dispersive.h, engine_ext_lorentzmaterial.h, engine_ext_debyematerial.h and the three
operator headers). Snapshots ~/opt/openEMS-dev/snap/cg22, cg23 (three dylibs, cgNN.patch vs 7bb294f, BASE). Neither is
installed (~/opt/openEMS is cg18). The libraries' version strings lag one commit, as with cg19-cg21.

Stage order per tile (the CPU engine's: Pre hooks in reverse extension order, Post and Apply in extension order;
UPML has the highest priority, Mur, lumped RLC and the dispersive extensions priority 0, the excitation -1000):
  E step: [Mur Pre, Lorentz Pre, Debye Pre]  (read the field only)  -> UPML Pre -> update -> UPML Post ->
          [Mur Post, Debye Post]  (read the field only) -> Apply list in extension order (Mur faces, lumped RLC,
          dispersive: field -= ADE per order) -> voltage excitation
  H step: Lorentz Pre (current ADEs) -> UPML Pre -> update -> UPML Post -> dispersive current Apply -> current excitation
