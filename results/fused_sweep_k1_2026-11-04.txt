# Step 2 of the 2026-11-04 plan: a fused, unblocked Metal sweep, measured as the K=1 case of the diamond engine
# (--engine=metal-diamond, OPENEMS_DIAMOND_K=1), snapshot cg27 (4127e1e). Apple M5 (10 GPU cores), macOS 27.0.1.
# At K=1 every threadgroup updates the voltages of its tile and then the currents of the same tile in one pass (the
# mountain, valley and mixed phases of the schedule complete the tile edges), so each field value is read and written
# once per time step: the 49 bytes per cell of the CPU's fused sweep (12 + 12 B of fields read and written per cell plus
# the operator index), against 74 B for an unfused engine (voltages and currents in separate passes).
# The question (paper/sec_beyond.tex): at the 121-127 GB/s the GPU kernels drew, 49 B per cell bounds a fused GPU sweep
# at about 2,470-2,590 million cells/s.
#
# A. Paired interleaved A/B on the two large models, 4 rounds (bench/abtest.py; others' CPU 2.5-4 cores, GPU 3-5 %).
#    MC/s median [min-max]; ratio to the default K=4; every run identical to c0's first run (and so to the
#    multithreaded CPU engine with OPENEMS_FTZ=1, results/*_cg27gpu.txt).

#
# Answer:
# - The fused, unblocked GPU sweep runs the two large models at 1,730-1,840 MC/s: 1.25-1.30x the unfused GPU engine,
#   0.85x (notch x3) and 1.07x (patch x5) the CPU's quiet-Mac best of cg18, and 67-75 % of the bound. At 49 B per cell that is 85-90 GB/s, not the 121-127 GB/s
#   the streaming kernels drew: the per-step structure (four dispatches, the tile edges, a threadgroup barrier between the
#   voltage and the current half step) costs more than the bytes it saves, and the bound is a traffic bound only.
# - Temporal blocking does what the fused sweep alone does not: K=2 runs 2,120-2,410 and K=4 2,820-2,990 MC/s, 14-21 %
#   above the fused bound, because the fields of a tile stay on chip across K time steps.
# - A dedicated one-dispatch fused kernel was not built: tiles that compute their edges themselves overwrite values their
#   neighbours still read in the same dispatch, so it needs a second copy of both fields (twice the field memory) and every
#   extension would have to follow; with K=4 already above its bound it would not make a model faster.
