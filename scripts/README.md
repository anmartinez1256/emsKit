# scripts/: the check and experiment scripts of the project

One line per script: what it does, its arguments, what it needs. Run directories go where the arguments say; the
scripts without such an argument write theirs next to themselves (`run_*`, `tmp_*`, `dry_*`, `r_*`; ignored by git,
like the reference run `s_ref` below). `checks/debye_check.sh` and `checks/diamond_check.sh` work in a temporary
folder that they remove, `cache_valley/placement.sh`, `kernel/gcc_vs_clang.sh` and `kernel/loop_insns.py` in
`${TMPDIR:-/tmp}/emskit_placement`, `emskit_gcc` and `emskit_loops`.
"RFSIM_PATH" means the environment variable that names the author's rfsim toolkit directory (the folder that contains
`rfsim/`). The toolkit is not public, and the changes made to it in this project are not published either, so the
scripts that need it can be rerun only where the toolkit is; what they measured is in `results/`. The table names
these commits of the toolkit: ed3ac3e (2026-11-01: the automatic thread count
and the z padding), 2948d58 (2026-11-01: the probe end option `probe_end_db`), 2b0fd8c (2026-11-04: the SMA launch's
mesh floor and the fixes of 2026-11-02 and 2026-11-03) and 4a7e20e (2026-11-04: the defaults since then, a 0.05 mm
floor and a hold of 0.5). The six toolkit Python scripts
(`probe_end/pend_run.py`, `zpad/zpad_full.py`, `sma_mesh/dry.py`, `sma_mesh/sweep.py`, `e2e/run_one.py`,
`timestep/export_gcpw.py`) stop with a `KeyError` when RFSIM_PATH is unset, `phases/phases.py` with a `RuntimeError`
(from `bench/models.py`) for `kgcpw` and `ksma`. For anything that mentions a fork knob (`OPENEMS_*`), the
`libopenEMS` that the Python module loads must be the fork's (installed, or chosen with `DYLD_LIBRARY_PATH`); the
module itself is upstream's, built against the installed headers (`BUILD.md`).

The reference run of `sma_mesh/batch.sh` (`REF`, default `../probe_end/s_ref`) is not in the repository: the full
10 ns SMA run on the toolkit's original 0.02 mm mesh (that of 2026-10-17), with the probe end criterion off. Make it
with the toolkit at commit 2948d58, because the mesh-floor change of 2b0fd8c moves 14 lines of that mesh
(`results/sma_mesh_sweep_2026-11-01.txt`). From this folder:
`DYLD_LIBRARY_PATH=LIB_DIR python3 probe_end/pend_run.py sma off 1 probe_end/s_ref` (182 s on the M5, same file;
`sp.npz` is written into the run directory). The end-to-end re-measurement of 2026-11-03 (`e2e/`) does not use it: its
reference is the full run on the 1.071 M-cell mesh of the toolkit's former 0.02 mm floor (`S_off` in
`results/rfsim_e2e_2026-11-03.txt`).

Run the Python scripts with plain `python3` and `DYLD_LIBRARY_PATH` set to the snapshot under test; do not put
`caffeinate` in front of `python3` (SIP strips `DYLD_*` for system binaries), start it beside the script instead. The
shell scripts take the library folder as an argument and set `DYLD_LIBRARY_PATH` for each `python3` call themselves:
a `DYLD_LIBRARY_PATH` set for the shell script would not arrive, because macOS drops `DYLD_*` when it starts
`/bin/zsh`. Either way `python3` must not be a macOS system binary such as `/usr/bin/python3`, which drops it too.
