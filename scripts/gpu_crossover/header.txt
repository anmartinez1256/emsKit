# GPU against CPU by grid size: snapshot cg29 (1620939), Apple M5 (4 P + 6 E cores, 10 GPU cores), macOS 27.0.1, 2026-11-05.
# The question (the author, 2026-11-05): at how many cells does the GPU engine become faster than the CPU engine, and why is
# it slower below that? Drawn in paper/figures/fig_crossover.py; text in paper/sec_gpu.tex ("Where the GPU overtakes the CPU").
#
# Method. Three bench models (bench/models.py) at several mesh scales: the patch antenna of the patch tutorial (scale 1
# = the patch tutorial, 0.104 M cells; scale 5 = patch x5, 7.863 M), the notch filter of the notch tutorial (scale 1 =
# the notch tutorial, 0.270 M; scale 3 = notch x3, 5.247 M) and the toolkit's GCPW line (scale 1 = the GCPW line of the
# tables, 0.242 M; its scale multiplies the cell size, so a smaller scale gives more cells). Each point is one paired,
# interleaved run of bench/abtest.py with 4 rounds; in every round the four configurations run in turn: c0 the
# multithreaded engine at 8 threads, c1 at 4 threads, c2 the metal-diamond engine, c3 the metal-diamond engine with
# OPENEMS_DIAMOND_TIMING=1 (GPU busy time per IterateTS call; c3/c2 over the points: see the checks). Every run waited
# (at most 1800 s) until the other processes used at most 150 % CPU and 10 % of the GPU, and was run again when they
# used more of either during it, up to 3 times (--quiet 150 --quiet-max 1800 --run-redo 3; the discarded runs are the
# raw output's "# redo" lines; one run, notch filter s1 r0 c1, went ahead after the 1800 s with the others at 774 %
# CPU, in a round that is left out). A round "kept after 3 redos" with a loaded run is left out of a point's medians
# when at least two clean rounds remain ("rounds": "3 of 4"; "N loaded" = fewer remained, so they are used). Steps:
# enough for a time loop of about 2 s on the small grids (36 500 on the patch tutorial), 3 000 on the large ones; the
# models' probes and dumps as in the bench (the patch's nf2ff dumps end an IterateTS call every 31 steps at scale 1).
# Passes (scripts/gpu_crossover/sweep.sh runs the same list in one go): 10:24-16:15 the first 21 points; 16:17-16:33 the
# GCPW line at 3.2 and 5.1 M cells and patch scales 2.5 and 3 again (their first pass had 3 of 4 rounds loaded; the
# table uses the re-runs, the first pass is in the raw output); 16:33-16:37 the run-length check (section 5);
# 16:37-16:42 the patch at 2.9 M and the GCPW line at 2.4 M cells, inside the two gaps around the crossover. Load: other
# sessions' builds and solvers, load average 1.7-17.5 at the start of a point; in the runs used the others took 0.5-1.3
# cores and 1-5 % of the GPU (median of a point; at most 1.5 cores and 9 %).
#
# Columns. MC/s = million Yee cells per second of the time loop (openEMS's own figure), median [min-max] over the rounds
# used; "*" marks the CPU thread count with the higher median (8 threads at every point). GPU / CPU best = median
# [min-max] of the per-round ratio of c2 to that thread count. From the c3 runs (median over the rounds used): GPU busy
# = GPU busy time / time loop; gaps = time inside IterateTS with the GPU idle (starting and finishing the call's command
# buffers); outside = time loop outside IterateTS (probes, dumps and the rest of the main loop, on the CPU); GPU-only =
# cells x steps / GPU busy time, the GPU's rate while it works; steps/call; GPU ms/call and idle ms/call = GPU busy and
# idle time per IterateTS call (idle = time loop - busy; on the large grids, with 4-28 calls per run, it includes the
# start and end of the loop); tiling = the tuner's choice (K, M,V) in the c3 runs used, with counts where they differ
# (the plain GPU runs do not report theirs); tiles/dispatch = tiles in one dispatch of each tiling listed, fewest (MM)
# to most (VV), x threads per tile, from a verbose 100-step run of the point; others = the other processes' CPU in cores
# and GPU in %, median [max] over every run used. Tiles, cells and probe checks: scripts/gpu_crossover/ (tiles.py,
# cells.py, analyze.py; mkresult.py assembles this file). The run folders with the probe files are not published.
